## Quick Start (Local)

### Prerequisites
- Node.js 20+
- PostgreSQL 14+ (local or remote)
- pnpm (recommended) or npm

### 1. Install dependencies
```bash
npm ci
# or
pnpm install
```

### 2. Set environment variables
```bash
cp .env.example .env
# Edit .env and fill in your values
```

### 3. Set up the database
```bash
# Create the standalone schema and import the deterministic tenant snapshot
npm run db:seed
```

### 4. Start development
```bash
# Start both server + frontend (concurrently)
npm run dev
```

Open http://localhost:5173 in your browser.

## Bootstrap administrator

No administrator password is shipped in this archive. Set BOOTSTRAP_ADMIN_USERNAME,
BOOTSTRAP_ADMIN_EMAIL, and BOOTSTRAP_ADMIN_PASSWORD (12+ characters) before the
first db:seed run; the importer creates that administrator only when no admin
exists. Remove BOOTSTRAP_ADMIN_PASSWORD after bootstrap.

## Deployment

### Deploy to Railway / Render / Fly.io
1. Attach a PostgreSQL database and set `DATABASE_URL`, `SESSION_SECRET`, `PUBLIC_BASE_URL`, and `UPLOAD_DIR`.
2. On the first seed only, set `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_EMAIL`, and `BOOTSTRAP_ADMIN_PASSWORD`.
3. Set build command: `npm ci && npm run build`; start command: `npm start`.
4. Configure SMTP secrets only if outbound email is needed.


For this Banking export, use the generated lockfile and configure:
- Build command: `npm ci && npm run build`
- Start command: `npm start`
- Health check path: `/readyz` (PostgreSQL and upload storage readiness)
- Railway: attach PostgreSQL and a Volume; set `DATABASE_URL` to the database URL and `UPLOAD_DIR` to the Volume mount path.
- Render: attach PostgreSQL and a persistent Disk; set `DATABASE_URL` to the database URL and `UPLOAD_DIR` to the Disk mount path.

Keep bootstrap admin variables set for the first start only, then remove
`BOOTSTRAP_ADMIN_PASSWORD`. Do not use an ephemeral filesystem for customer uploads.


### Persistent customer documents
The runtime stores private KYC uploads on the local filesystem. For hosted deployments, attach a durable
volume and set `UPLOAD_DIR` to its mount path before starting the app. Production startup fails if this
variable is missing. Do not use an ephemeral container path, and do not run multiple app replicas unless
they share the same durable upload storage. Docker Compose includes a named `uploads` volume mounted at
`/app/data/uploads`.

### Deploy to VPS
1. Install Node.js 20+ and PostgreSQL
2. Clone / upload project files
3. `npm install && npm run build`
4. Use PM2: `pm2 start npm --name "avenqora-bank" -- start`

### Email configuration

The exported website contains this website's non-secret email identities and notification templates only.
It never contains SMTP credentials and does not call the Danzy GLE platform at runtime. Configure
`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, and `SMTP_PASS` as hosting-provider secrets to enable outbound email.
Without SMTP, in-app notifications still work, but email delivery and password-reset messages are unavailable.
The Main System Email sends automated notifications; the Customer Support Email is inquiry-only.
Changes made in the standalone admin email settings are stored in that website's own database.

### External services and functional limits

- **Runtime independence:** after export, the website runs from its own PostgreSQL database and local files. It does not call the Danzy GLE API or require Replit runtime services. Source media is copied into the archive during export; source-platform storage is not used by the exported runtime.
- **Uploads:** uploaded customer documents and owner media use `UPLOAD_DIR`. Production deployments must mount durable storage there; use shared storage if running multiple app replicas.
- **Payments:** no card processor or external payment gateway is bundled. Payment evidence is submitted for local administrator review. Banking Zelle and Sending Order requests are internal review requests; approval does not send money.
- **Market data:** Forex and crypto quote endpoints use fixed sample values, not a live market-data provider. Do not use them as current prices or for real trading.
- **Live chat:** the optional configured widget loads directly in the visitor's browser from its provider (for example, Smartsupp, Tawk.to, Crisp, Intercom, Zendesk Chat, or LiveChat). It requires that provider's service and an internet connection; provider credentials are not included.
- **External media:** any external asset references are listed in `manifest.json` under `contents.assets.externalReferences`; those URLs continue to depend on their original hosts.

### Package Tracking automation

Tracking exports include a local worker that advances eligible shipments every minute using the
exported journey configuration. It writes automatic tracking events into the exported database,
stops at destination, and leaves manually overridden, held, delayed, delivered, completed, and
cancelled shipments unchanged.
